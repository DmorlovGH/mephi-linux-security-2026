## Задание № 2. Поиск SUID-файлов и процессов

### Требование

Найти:

1. Все файлы с установленным битом SUID.
2. Процессы, у которых эффективный UID равен 0,
   а реальный UID принадлежит обычному пользователю.

### Реализация

Для поиска SUID-файлов использована команда:

```bash
sudo find / -type f -perm -4000 -print 2>/dev/null
```

Для поиска процессов использована команда:

```bash
ps -eo pid,ruid,euid,user,comm |
awk 'NR==1 || ($2!=0 && $3==0)'
```

### Проверка

Обнаружен процесс `passwd` со следующими параметрами:

- Real UID (RUID): 1000;
- Effective UID (EUID): 0;
- пользователь с реальным UID: `mephiadmin`.

Таким образом, подтверждена работа механизма SUID,
позволяющего процессу использовать эффективные
полномочия владельца исполняемого файла.

### Подтверждающие файлы

- `suid-files.out`
- `suid-processes.out`

## Задание № 3. Повышение привилегий с помощью SUID

### Требование

Выбрать существующую системную утилиту, создать её копию
и настроить SUID для выполнения операции,
требующей повышенных привилегий.

### Реализация

Выбрана стандартная утилита:

```text
/usr/bin/cat
```

Создана копия:

```text
/home/mephiadmin/bos-lab/cat-suid
```

Для копии настроены:

- владелец — `root`;
- группа — `root`;
- права доступа — `4755`.

Команды настройки:

```bash
sudo chown root:root ~/bos-lab/cat-suid
sudo chmod u+s ~/bos-lab/cat-suid
```

### Проверка

Обычный пользователь не может непосредственно
прочитать защищённый файл `/etc/shadow`.

При этом копия `cat` с установленным SUID
успешно выполнила чтение этого файла
без использования `sudo`.

Проверочная команда:

```bash
~/bos-lab/cat-suid /etc/shadow > /dev/null
```

Код завершения:

```text
0
```

Вывод перенаправлен в `/dev/null`, чтобы не раскрывать
содержимое защищённого файла.

### Подтверждающие файлы

- `suid-test.out`
- `stat.out`

### Примечание по безопасности

Назначение SUID обычной утилите чтения файлов
создаёт серьёзную угрозу безопасности.

Данная конфигурация использовалась исключительно
для демонстрации механизма повышения привилегий
в изолированной учебной виртуальной машине.

## Задание № 4. Использование Linux Capabilities

### Требование

Выбрать существующую утилиту, создать её копию
и предоставить ей отдельную привилегию Linux Capabilities
для выполнения операции без полномочий root.

### Реализация

Выбрана утилита:

```text

```

Создана копия:

```text
/home/mephiadmin/bos-lab/chown-cap
```

Для неё назначена привилегия:

```bash
sudo setcap cap_chown+ep ~/bos-lab/chown-cap
```

### Проверка

Создан тестовый файл:

```text
/home/mephiadmin/bos-lab/test-cap.txt
```

Попытка изменить владельца стандартной командой `chown`
без `sudo` завершилась ошибкой:

```text
Operation not permitted
```

После запуска копии утилиты с `CAP_CHOWN`
владелец файла был успешно изменён на `user1`.

Проверка назначенной привилегии:

```bash
getcap ~/bos-lab/chown-cap
```

Результат:

```text
/home/mephiadmin/bos-lab/chown-cap cap_chown=ep
```

## Задание № 5. Делегирование полномочий через sudo

### Требование

Предоставить пользователю `user1` право
изменять системное время с использованием `sudo`.

### Реализация

Создан отдельный файл конфигурации:

```text
/etc/sudoers.d/user1-time
```

Содержимое правила:

```text
user1 ALL=(root) /usr/bin/timedatectl set-time *
```

Правило разрешает пользователю `user1`
запускать команду изменения системного времени
от имени `root`.

### Проверка конфигурации

Выполнена команда:

```bash
sudo visudo -c
```

Результат:

```text
/etc/sudoers: parsed OK
/etc/sudoers.d/user1-time: parsed OK
```

Дополнительно проверены разрешения пользователя:

```bash
sudo -l -U user1
```

Подтверждено наличие разрешения:

```text
(root) /usr/bin/timedatectl set-time *
```

### Функциональная проверка

Для проверки фактического изменения системного времени:

1. Временно отключена синхронизация NTP.
2. Выполнен вход под пользователем `user1`.
3. Через `sudo timedatectl set-time` выполнено
   изменение системного времени.
4. Подтверждено успешное выполнение команды (код завершения `0`).
5. После эксперимента синхронизация NTP восстановлена.

Проверка выполнена от имени `user1` (UID 1234).
Время до изменения: `04:35:22 EDT`.
Время после изменения: `04:38:00 EDT`.
Дата проверки: 13 октября 2026 года.

Использована команда:

    sudo /usr/bin/timedatectl set-time "$(date -d '+2 minutes' '+%Y-%m-%d %H:%M:%S')"

Результат: `EXIT CODE: 0`.
Подтверждение: `time-change-proof.out` — протокол,
подготовленный из записи реальной терминальной сессии.

Контроль состояния:

```text
System clock synchronized: yes
NTP service: active
```

### Подтверждающие файлы

- `sudoers`
- `user1-time`
- `sudo-test.out`
- `time-change-test.out`
- `time-change-proof.out`

## Примечания по информационной безопасности

Работа выполнена в учебной виртуальной машине.

Файл `shadow` является обезличенной копией
системного файла `/etc/shadow`.

Во всех записях хеши паролей заменены символом `!`.

Это позволяет продемонстрировать параметры
учётных записей и политики паролей
без публикации конфиденциальных данных.

Исходный файл `/etc/shadow` не изменялся.

Исполняемые файлы с установленным SUID
и назначенными Linux Capabilities
в публичный репозиторий не включены.

После завершения экспериментов повышенные привилегии
отключены: у `cat-suid` снят бит SUID, у `chown-cap`
удалена файловая привилегия `CAP_CHOWN`.
Результаты экспериментов сохранены в отчётных файлах.
